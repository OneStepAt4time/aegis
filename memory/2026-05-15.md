## 22:35 CEST — P0 #3479 Investigation: ROOT CAUSE FOUND

### Root Cause
**CC 2.1.92 does NOT implement ACP protocol.** The `session/prompt`, `session/new`, `session/close` methods do not exist in this version.

- Installed CC: 2.1.92
- Latest CC: 2.1.142
- CC 2.1.92 only supports MCP methods (initialize, tools/call, resources/read, notifications/message, etc.)
- ACP session methods were added in later CC versions

### Secondary Bug: False Positive delivery
- `sendPrompt()` in backend.ts uses `notify()` (fire-and-forget JSON-RPC)
- JSON-RPC notifications do NOT receive responses — not even error responses
- When CC returns `-32601 Method not found`, Aegis never sees it
- Result: `promptDelivery.delivered: true` despite failure

### Two Bugs, One Root Cause
1. CC too old → no ACP methods → `session/prompt` = Method not found
2. `sendPrompt()` uses `notify()` → error silently swallowed → false `delivered: true`

### Action Needed
- **Operator action:** Update CC from 2.1.92 to 2.1.142
- **Code fix:** Change `sendPrompt()` to use `request()` instead of `notify()` to catch errors properly
- **Code fix:** Add error handling for `-32601` responses even in notify path

### Related
- #3479: CC prompt delivery broken
- #3480: ACP bridge events (related but different bug)
- #3423: Previous prompt delivery fix (switched to notify — introduced false positive)
